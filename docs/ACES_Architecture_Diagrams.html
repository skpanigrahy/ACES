C4 — CODE DIAGRAM
Key Classes & Interfaces
The plugin contract and core domain models. These are the stable interfaces every engineer must understand. Changing these after Phase 1 requires a version bump.
🔌
AgentPlugin Interface — THE Core Contract
com.jpmc.aces.common.plugin.contract
// Every AI agent that runs on ACES must implement this interface. // Versioned. Stable after Phase 1. Do not change without a version bump. public interface AgentPlugin { // Required: plugin identity — declared in plugin.json PluginManifest getManifest(); // Required: health check — called every 60s by PluginHealthMonitor HealthStatus ping(); // Required: execute a task — agentReasoning in response is MANDATORY AgentResponse execute(AgentRequest request); // Required: return execution metadata for audit ExecutionMetadata getExecutionMetadata(String executionId); // Optional: cancel in-flight execution default void cancel(String executionId) {} // Optional: estimate cost before execution default CostEstimate estimateCost(AgentRequest req) { return null; } }

aces-common · IR model
public record AgentRequest( String executionId, String taskType, AgentContext context, ExecutionConstraints constraints, AriaContext ariaContext // MANDATORY — injected by ARIA ) {} public record AriaContext( double trustScore, String trustBand, List<String> activeConstraints, // agent MUST respect these String priorDecision ) {}

aces-common · IR model
public record AgentResponse( String executionId, ExecutionStatus status, List<Artifact> artifacts, int tokenCount, long durationMs, String agentReasoning, // NEVER null, NEVER empty Double confidence ) {} // agentReasoning feeds Decision Archaeology in ARIA. // If empty → validation fails → PR blocked.

• Package: com.jpmc.aces.{module}
• Class hierarchy + Spring annotations
• @Service, @Repository, @Controller
• Constructor injection pattern
• Oracle JPA entity structure
• Error handling skeleton
• Test class (JUnit 5)
• Logging (SLF4J)
• OpenTelemetry span wrapping
LLM FILLS IN (Intelligent)
• Business logic in service methods
• Domain-specific validation rules
• Oracle SQL for this service
• Vector Search embedding logic
• Agent prompt templates
• Tool integration specifics
• Domain error messages
• Business exception types
• Domain test scenarios
OUTPUT (Consistent + Smart)
• Complete Spring Boot service
• Consistent arch across all modules
• Oracle 23ai integration working
• Tests that actually pass
• ARIA governance hooks wired
• Audit logging configured
• OTel traces instrumented
