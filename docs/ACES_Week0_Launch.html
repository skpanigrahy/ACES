PROJECT LEAD BRIEFING
Why Week 0 Exists
The biggest risk on a greenfield project is not technical. It is misalignment. Teams that skip Week 0 spend Sprint 1 building in five directions and Sprint 2 tearing it down. Week 0 costs 5 days and saves 3 sprints.
THE RULE OF GREENFIELD PROJECTS
No engineer writes domain code until: (1) everyone has read the architecture document, (2) every engineer can answer "what layer does my code live in?", (3) the project scaffold is committed and everyone has pulled it. These three gates must be cleared before Sprint 1 Day 1.

DAY 2 DELIVERABLE
5 Architecture Decisions to Lock on Day 2
These decisions cannot be undone cheaply once Sprint 1 starts. Lock them on Day 2. Write them down. Commit them to the repo wiki.
🏗
Decision 1: Project Structure — Modular Monolith (NOT microservices)
Start as a modular monolith. One Spring Boot app, multiple internal modules with strict package boundaries. Extract to microservices in Phase 3 only if needed. Microservices on Day 1 = operational overhead that kills a small team.
✓ RECOMMENDED: Modular monolith → Phase 3 extraction if justified
📚
Decision 2: AI Framework — LangChain4j (not Spring AI)
LangChain4j has native MCP tool support, better agent loop abstractions, and more active Java AI community. Spring AI is cleaner but thinner. For ACES specifically, LangChain4j wins on MCP integration depth.
✓ RECOMMENDED: LangChain4j 0.35+ with MCP tool provider
🗄
Decision 3: Database — Oracle ADB with Flyway migrations
Oracle Autonomous Database with wallet-based connection. Flyway for schema migrations — every DDL change is versioned and reproducible. HikariCP for connection pooling. No ORM for complex queries — use JDBC templates for performance-critical paths.
✓ RECOMMENDED: Oracle ADB + Flyway + HikariCP + Spring Data JPA for simple + JdbcTemplate for complex
🌿
Decision 4: Git Strategy — Trunk-based development
Feature branches live max 2 days. PR required before merge to main. One reviewer minimum. No long-lived feature branches. Main is always deployable. This forces small, reviewable commits and prevents integration hell.
✓ RECOMMENDED: Trunk-based + feature flags for incomplete features
📦
Decision 5: Package naming convention
com.jpmc.aces.{module}.{submodule} — strict. No exceptions. The package name tells you exactly which architectural layer the class belongs to. If you cannot tell from the package name, it is in the wrong package.
✓ LOCKED: com.jpmc.aces.core.orchestrator, com.jpmc.aces.mcp.auth, etc.

After Week 0 — What Happens on Sprint 1 Day 1
Sprint 1 Day 1 is not planning. Planning happened on Week 0 Day 5. Sprint 1 Day 1 is coding. Every engineer opens their first ticket and starts work.
SPRINT 1 DAY 1 MORNING STANDUP — THE ONLY AGENDA ITEM
Each engineer says: "I am working on ACES-{num}. My first commit will be [specific thing]. I expect to be done by [day]." That is it. No retrospective. No re-planning. Build.
THE FIRST COMMIT RULE
Every engineer must make their first commit by end of Sprint 1 Day 1. Even if it is a skeleton class with a TODO. A commit proves the environment works and the engineer is unblocked. No first commit by end of Day 1 = blocker that Santosh resolves immediately.
