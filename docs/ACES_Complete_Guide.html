THE INSIGHT YOU HAD
You are not asking ACES to build itself. You are asking: can we use Claude Code with CLAUDE.md instructions, skill files, and module specs to generate each ACES module — one per engineer — so we finish faster? The answer is YES. This is exactly how the best teams build with AI today. It cuts Phase 1 from 8 weeks to 10 days.
HOW IT WORKS — THREE INGREDIENTS
1. CLAUDE.md (Project Instructions)
→Lives at project root. Claude Code reads it automatically before every generation.
→Defines: package conventions, Oracle 23ai connection, Spring AI setup, style rules, non-negotiables.
→Same mental model for ALL 6 engineers. Claude generates consistent code across all modules.
→Acts as the architectural guardrail — if Claude violates CLAUDE.md, the PR reviewer catches it.
2. Module Spec Files
→One .md spec per module. Engineer 1 gets aces-mcp-spec.md. Engineer 2 gets aces-core-spec.md.
→Spec defines: classes to generate, methods, logic, Oracle tables, metrics, test cases.
→Engineer feeds spec to Claude Code. Claude generates ALL files in the module.
→Engineer reviews every line. Fixes issues. Raises PR. 4-6 hours instead of 2 weeks.
3. Skill Files
→Reusable patterns Claude applies across all modules.
→oracle-vpd-pattern.md — correct Oracle VPD usage every time.
→spring-ai-agent-pattern.md — correct Spring AI wiring every time.
→No engineer writes boilerplate. Claude handles it consistently.
4. The Review Rule
→AI generates. Engineer reviews EVERY LINE before committing.
→This is not vibe coding. The engineer must understand what was generated.
→PR review by second engineer: does it follow CLAUDE.md? Does it follow the spec?
→If engineer cannot explain a generated line — rewrite it or ask Claude to explain it.

ACES AUTO-FIX USE CASE
CI/CD Signal → ARIA Governs → ACES Fixes → Pipeline Retriggers
Engineer does nothing except review a single commit. Snyk finds vulnerability. ACES reads it, generates the fix, commits it, retriggers the build. 45 minutes → 2 minutes.
IS THIS CORRECT?
Yes — exactly correct. This is ACES doing what ACES does. It is not a separate platform. It is a use case: Integration Layer receives Snyk webhook → ARIA evaluates risk → ACES agent generates fix → commits to PR branch → retriggers pipeline → notifies engineer. The engineer reviews one commit. That is all.
